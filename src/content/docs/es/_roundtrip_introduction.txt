**An Efficient and Opinionated Guide to Images for 2023**

Check the sidebar for an in-depth analysis. This is the quick reference to update those `<img>` tags and handle modern devices in all their various sizes and pixel densities. You should [know that pixels != pixels](/en/pixels-not-pixels) and `devicePixelRatio` is more likely to be around 3.875 than 1:1. Modern phones claim to be 320-428px wide for readability (in CSS pixels), but have many device pixels per CSS pixel.

> If your image never resizes, no matter how narrow you make the browser window, you should use a [density descriptor](/en/density-descriptors) instead. This is often suitable for logos, icons, and buttons.

Do you know your [breakpoints](/en/breakpoints)? You'll need those numbers to fine-tune the solution below – and at a minimum, the viewport width breakpoint where the main content area stops growing.

### The easy method

```html

<img src="img.jpg?w=480" 
     srcset="img.jpg?format=webp&w=480 480w, 
             img.jpg?format=webp&w=800 800w, 
             img.jpg?format=webp&w=1200 1200w, 
             img.jpg?format=webp&w=1600 1600w, 
             img.jpg?format=webp&w=2000 2000w"

     sizes="(max-width: 700px) 100vw, 800px" alt="Dog riding a bicycle" />

<!-- We've assumed you have a breakpoint at 700px. 
     And that under that viewport width, this image takes up 100% of the width, but
     when the viewport is larger, the image is limited to 800 CSS pixels -->

<!-- This assumes you're using an RIAPI-compatible image server, like Imageflow. 
     Producing image variants on the fly is essential for developer sanity. -->
```
