### Background

Small screens and large displays require different layouts. For the purposes of `srcset` and `sizes`, we need to know at which point the layout changes.

Web developers have to decide what content to shrink, hide, or reposition on small screens—or more commonly, what to expand, show, or add on larger screens. And they have very little information to go by. Is the user on a tablet or in landscape mode on a phone—or is it just a small browser window?

We must choose an arbitrary viewport width to change the layout. This is known as a **breakpoint**. It's an arbitrary CSS pixel ([not a device pixel](/en/pixels-not-pixels)). Polypane has a [great article](https://polypane.app/blog/the-breakpoints-we-tested-in-2021-and-the-ones-to-test-in-2022/#the-breakpoints-to-develop-on-in-2023) about breakpoints commonly used.

Some images (like logos, icons, or buttons) might not be affected by layout changes caused by these breakpoints (for those, you can use [srcset density descriptors](/en/density-descriptors)).

Main content images will be constrained by the size of their container. Typically, the main content area of a page is constrained to a specific width, `max-width`, on the largest screens, but on smaller screens, the main content area takes up the entire viewport.

If you have more than one column of content at certain breakpoints, calculating effective size rules becomes more complicated because the percentage of viewport width taken up by images changes.

### Simple Method

That said, don't overthink it. The following approximate method might be suitable:

1. What is the size at which the main column (or container for the images) stops growing? Within this viewport width range, we can use `100vw` for the `sizes` attribute of images, meaning that the image takes up 100% of the viewport width.  
2. What is the maximum width that the container can reach? We can set this as a fixed `width` for everything else.

If your answer to 1 is 700px, and to 2 is 800px, you can use the following `sizes` attribute:

```html
<!-- These are CSS pixels, not device pixels or image pixels. -->
<img [...] sizes="(max-width: 700px) 100vw, 800px"  />
```

> You might think that the browser could handle all this calculation well according to the CSS. Unfortunately, browsers are eager to choose an image URL before the stylesheets download. So we have to do the calculations ourselves, and if not perfectly, that's what they deserve.
