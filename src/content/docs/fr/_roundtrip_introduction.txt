**An Efficient and Confident Guide for Images in 2023**

Check the sidebar for an in-depth examination. Here is a quick reference for updating these `<img>` tags to handle modern devices in all their varied sizes and pixel densities. You should [know that pixels != pixels](/en/pixels-not-pixels) and that `devicePixelRatio` is more likely to be around 3.875 than 1:1. Modern phones claim to be 320-428px wide for better readability (in CSS pixels), but have many device pixels per CSS pixel.

> If your image never changes size, no matter how wide the browser window is, you should use a [density descriptor instead](/en/density-descriptors). This is often suitable for logos, icons, and buttons.

Do you know your [breakpoints](/en/breakpoints)? You will need these numbers to fine-tune the solution below - and at a minimum the viewport width breakpoint where the main content area stops growing.

### The Easy Method

```html

<img src="img.jpg?w=480" 
        srcset="img.jpg?format=webp&w=480 480w, 
                img.jpg?format=webp&w=800 800w, 
                img.jpg?format=webp&w=1200 1200w, 
                img.jpg?format=webp&w=1600 1600w, 
                img.jpg?format=webp&w=2000 2000w"

        sizes="(max-width: 700px) 100vw, 800px" alt="Dog riding a bike" />

<!-- We have assumed you have a breakpoint at 700px. 
      And that below this window width, this image takes 100% of the width, but 
      when the window is larger, the image is limited to 800 CSS pixels -->

<!-- This assumes you are using an RIAPI-capable image server such as Imageflow. 
     Producing image variants on the fly is essential for developer peace of mind. -->
```
