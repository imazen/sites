### Device pixels ≠ browser pixels ≠ image pixels

Thanks to Apple, CSS and HTML pixels (`px`) **almost always correspond to multiples of device/printer pixels**. The devicePixelRatio on my phone is 3.875; [what's yours?](https://www.mydevice.io/)

My devicePixelRatio on the desktop changes with the browser zoom, but by default, it's 1.5 (since my `System > Display > Scale` is 150%, after all).

Image files (excluding SVGs) decode into a grid of pixels. **It is annoyingly difficult to get image pixels to display perfectly in a 1:1 ratio with device pixels - but with `srcset`, you can get pretty close***, and a bit of JavaScript can adjust the HTML element size after loading if you have truly justified reasons to have that accurate match, although such forbidden arts will not be revealed here.

> Other [absolute units (in, pc, pt, mm, cm, Q)](https://developer.mozilla.org/en/docs/Web/CSS/length) are defined in terms of the number of CSS pixels and pretend everything is 96dpi. Developers avoid absolute units because, in general, it's better to use units derived from font size or viewport/container sizes. Mismatched units can break a layout if the user adjusts their `Accessibility > Text size` multiplier, the browser zooms, or the device rotates. Needless to say, you should do all of these things before launching your site.
