### Device Pixels ≠ Browser px ≠ Image px

Thanks to Apple, CSS and HTML pixels (`px`) **almost always map to multiple device/printer pixels**. The devicePixelRatio on my phone is 3.875. What is yours? [Find out here.](https://www.mydevice.io/)

On desktops, the devicePixelRatio changes with browser zoom but defaults to 1.5 (since `System > Display > Scale` is set to 150%).

Image files (excluding SVGs) are decoded into a pixel grid. **Perfectly displaying the image's pixels as a 1:1 ratio with device pixels is tricky—but you can get quite close using `srcset`**. If there is a truly justified need for perfect mapping, you can adjust the sizes of HTML elements after loading with a bit of JavaScript, although such forbidden techniques will not be revealed here.

> Other absolute [units (in, pc, pt, mm, cm, Q)](https://developer.mozilla.org/en/docs/Web/CSS/length) are defined by a constant number of CSS pixels and behave as if everything is 96dpi. Developers tend to avoid absolute units because using those deriving from font sizes or viewport/container dimensions is usually better. If a user adjusts `Accessibility > Text Size` scaling, zooms in on a browser, or rotates their device, mismatched units can break a layout. Needless to say, you should test all of these before publishing your site.
