### Background

Different layouts are necessary for small screens and large monitors. For `srcset` and `sizes`, it is essential to know at which point the layout changes.

Web developers have to decide what to shrink, hide, or move on smaller screens - or, more commonly, what to expand, reveal, or add on larger screens. However, they have very little information. Are users on a tablet, a phone in landscape mode, or just a small browser window?

We must choose any viewport width where the layout changes. This is called a **breakpoint**. It is an arbitrary number of CSS pixels ([not device pixels](/ja/pixels-not-pixels)). Polypane has a [great article](https://polypane.app/blog/the-breakpoints-we-tested-in-2021-and-the-ones-to-test-in-2022/#the-breakpoints-to-develop-on-in-2023) on commonly used breakpoints.

Some images (like logos, icons, buttons, etc.) are unaffected by layout changes triggered by these breakpoints (and are fine with the [srcset density descriptor](/ja/density-descriptors)),

The images in the main content are limited by the size of their container. Typically, the main content area on a page is constrained to a specific width on a large screen, thanks to a `max-width`, while on a small screen, the main content area fills the entire viewport.

If there is more than one column at a breakpoint, calculating an effective size rule becomes challenging because the portion of the viewport width occupied by the image can change.

### The Easy Way

That aside, don’t overthink this. You’re probably very fine with the following approximation:

1. Where does the main column (or image's container) stop growing? Up to that viewport width, you can use `100vw` in the image's `sizes` attribute to say the image occupies 100% of the viewport width.
2. What is the maximum width that container achieves? Set that as a fixed `width` for everything else.

If the answer to 1 is 700px, and the answer to 2 is 800px, you can use the following `sizes` attribute:

```html
<!-- These are CSS pixels. Not device pixels or image pixels. -->
<img [...] sizes="(max-width: 700px) 100vw, 800px"  />
```

> You might think browsers could handle these calculations well based on CSS. Unfortunately, browsers are eager to pick image URLs *before* style sheets are downloaded. Therefore, we have to do the calculations ourselves or punish the browser for being incomplete.
